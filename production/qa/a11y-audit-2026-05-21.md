## Methodology

- Static analysis via `grep` + `Read`: scan for known anti-patterns (non-button
  onclick handlers, missing aria labels on icon-only buttons, form inputs without
  labels, dialog focus management, ARIA role correctness).
- Cross-check against the binding rules in `design/ux/accessibility-requirements.md`
  Sections 1-7 (Contrast, Color, Reduced Motion, Text Scaling, Time Pressure,
  Cognitive Load, Keyboard, Forms, Dialogs).
- DaisyUI defaults: assumed compliant for contrast (the project uses standard
  daisyUI themes which are AA-compliant out of the box).

## Findings — Severity Grouped

### P0 (Basic / AA blocker — fix this sprint) — 4 findings

| # | Location | Violation | Recommended fix |
|---|---|---|---|
| **P0-1** | `apps/web/src/routes/staff/+page.svelte:185-198` — Despedir icon button | `<button>` uses `title="Despedir"` only; no `aria-label`. Icon "✕" is meaningless to screen readers without explicit label; `title` is unreliable on mobile + assistive tech. | Add `aria-label={'Despedir a ' + current.name}` (already references the staff member's name in title for sighted users — just promote to aria-label). |
| **P0-2** | `apps/web/src/lib/components/confirm-dialog.svelte:48` — modal | `role="dialog" aria-modal="true"` but no `aria-labelledby` linking to the title `<h3>`. Screen readers won't announce the dialog title when it opens. | Add `id="dialog-title"` to the `<h3>` and `aria-labelledby="dialog-title"` to the modal `<div>`. |
| **P0-3** | `apps/web/src/lib/components/confirm-dialog.svelte:65-72` — ESC handling | ESC keydown is on the backdrop element with `tabindex="-1"`; the backdrop never receives focus, so ESC never fires. Users without a mouse cannot dismiss the dialog. | Move the `onkeydown` ESC handler to the modal `<div role="dialog">` so it fires on any focus state inside the modal. |
| **P0-4** | `apps/web/src/routes/finance/+page.svelte:220-227` — native ticket-price slider | The native `<input type="range">` fallback (added in B2 fix) has no `aria-label`. Range inputs MUST be labeled for AA compliance — the surrounding context "Precio de abono" is visual only. | Add `aria-label="Precio del abono en euros"` to the `<input type="range">` element. |

### P1 (should fix in Polish but not blocking) — 6 findings

| # | Location | Violation | Recommended fix |
|---|---|---|---|
| **P1-1** | `apps/web/src/lib/components/confirm-dialog.svelte` (focus trap) | No focus trap — Tab can leave the modal to the page behind it. WCAG 2.1 AA technically allows this (no SC explicitly requires focus trap on dialogs), but it's a standard usability expectation. | Add a Svelte action `use:focusTrap` or implement `focus()` on the first button when the dialog opens, and listen for Tab on the last button to wrap back. |
| **P1-2** | `apps/web/src/lib/components/confirm-dialog.svelte` (focus return) | When the dialog closes, focus is lost (returns to `<body>`). It should return to the element that opened the dialog. | Capture `document.activeElement` in `$effect` when the dialog opens, restore it in `handleCancel` / `handleConfirm`. |
| **P1-3** | `apps/web/src/lib/components/advance-transition.svelte` (modal focus) | Same focus-trap + focus-return gap as confirm-dialog. The modal is non-interactive (informational), so the impact is lower, but a screen reader still loses its place. | Apply the same focus-management pattern as P1-1 / P1-2. |
| **P1-4** | All tab bars (`/finance`, `/league`, `/inbox`) — `role="tablist"` + `role="tab"` | Tabs use `<button role="tab">` correctly but don't set `aria-selected="true/false"` per tab, and `aria-controls` is missing. Screen readers can't announce "1 of 3, selected". | For each tab, add `aria-selected={activeTab === 'X'}` and `aria-controls={'tabpanel-X'}`; the corresponding tab content should set `role="tabpanel" id="tabpanel-X"`. |
| **P1-5** | `apps/web/src/routes/match/[matchSessionId]/+page.svelte` — match replay live region | Match-event ticker updates dynamically with goals/events but has no `aria-live="polite"` region announcement. Screen readers will not announce a goal as it happens. | Wrap the event log in a `<div aria-live="polite" aria-atomic="false">`. |
| **P1-6** | `apps/web/src/lib/components/topbar.svelte` — balance color | The balance number uses color alone to convey "in the red" (`text-error` when negative). Reduced-color users miss the signal. The dashboard has `<` prefix only for negative numbers via CSS, but there's no explicit prefix/icon. | Add an icon (e.g., ⚠) or a text prefix ("−") to the balance value when financialStatus ≥ 2. The existing red color is supplementary, not primary. |

### P2 (nice to have — Polish backlog candidates) — 3 findings

| # | Location | Violation | Recommended fix |
|---|---|---|---|
| **P2-1** | All routes | No skip-to-content link (`<a href="#main">Saltar al contenido</a>`) at top of layout. Keyboard users must Tab through the sidebar before reaching page content. | Add a visually-hidden-until-focused skip link in `+layout.svelte` that jumps to `<main id="main">`. |
| **P2-2** | `apps/web/src/routes/league/+page.svelte` — standings table | Table has no `<caption>`. Helpful for screen readers to announce table purpose. | Add `<caption class="sr-only">Clasificación de la liga · {data.standings.length} equipos</caption>` inside the `<table>`. |
| **P2-3** | All routes — heading hierarchy | Each route has its own `<h1>`, but several pages skip to `<h3>` from `<h1>` without an intervening `<h2>`. Not strictly an AA violation (3.1.1) but flags in axe-core. | Insert section-level `<h2>` headings or downgrade some `<h3>` to `<h2>` to maintain a proper hierarchy. |

## Verdict

**CONDITIONAL PASS — 4 P0 fixes scheduled this sprint.**

The codebase shows strong baseline a11y hygiene:
- All onclick handlers attached to `<button>` or `<a>` elements (no `<div onclick>`).
- Most icon buttons in the topbar already have `aria-label`.
- Sponsor-offer dialog uses `aria-labelledby` correctly (`finance/tv-rights:208`).
- Bucket-group component uses `role="radiogroup"` correctly.
- DaisyUI theme provides AA contrast out of the box.
- `prefers-reduced-motion` is respected by Tailwind utilities used throughout.

The 4 P0 fixes are surgical (one-line additions per finding). The 6 P1 findings
form a coherent Polish-phase backlog item ("dialog + tab a11y completion pass")
that should land in Sprint 11 or 12. The 3 P2 findings are non-blocking
polish items.

## Fix Plan (this sprint)
