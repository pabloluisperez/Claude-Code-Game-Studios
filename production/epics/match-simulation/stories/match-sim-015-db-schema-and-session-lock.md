# Story: match_sessions Table + Partial UNIQUE INDEX + Repository

## Goal

Define the `match_sessions` Drizzle table that stores `MatchSessionSnapshot` between BullMQ job executions. The table is the durability layer for ADR-013 Option B.

**Critical constraint**: partial UNIQUE INDEX `match_sessions_active_playthrough` that excludes states `'completed' | 'archived' | 'failed'`. This is what prevents two active sessions per playthrough (the session lock). The slice verified that Drizzle 0.36+ requires the `sql` template literal in the `.where()` clause — not a raw string. Otherwise `drizzle-kit generate` fails silently.

This is the FIRST story in this epic that touches the database. Real Postgres on port 5433.

  - `player_club_id` (uuid).
  - `pre_match_snapshot` (jsonb).
  - `created_at` (timestamp default now()).
  - `updated_at` (timestamp default now() on update).
- **Partial UNIQUE INDEX**:
  ```ts
  uniqueIndex('match_sessions_active_playthrough')
    .on(table.playthroughId)
    .where(sql`${table.state} NOT IN ('completed', 'archived', 'failed')`)
  ```
  Use `sql` template literal in `.where()` — control-manifest Foundation Required. Raw string fails drizzle-kit.
- Standard index: `(playthrough_id, created_at DESC)` to support "find active session" queries.

In `apps/api/src/modules/match/match-sessions-repo.ts` (new):

- `createSession(tx, input: MatchInput, initialSnapshot: MatchSessionSnapshot): Promise<{ id: string }>` — INSERT. If the UNIQUE INDEX fires (active session exists), throw a typed error `MatchSessionConflictError` that the HTTP layer translates to 409.
- `findActiveSession(playthroughId: string): Promise<MatchSessionRow | null>` — canonical query: `WHERE state NOT IN ('completed', 'archived', 'failed') ORDER BY created_at DESC LIMIT 1` (R6 fix — without ORDER BY, a `failed` row could outsort an `in_progress` if findFirst is used).
- `updateSnapshot(tx, sessionId: string, snapshot: MatchSessionSnapshot): Promise<void>` — UPDATE prng_state, events, lineups, state, timeoutJobId, etc.
- `markFailed(tx, sessionId: string, reason: string): Promise<void>` — set state='failed' + log reason in a separate audit row.
- `markCompleted(tx, sessionId: string, outcome: MatchOutcome): Promise<void>` — set state='completed' + persist final score (denormalized for fast reads).
- `acquireForUpdate(tx, sessionId: string): Promise<MatchSessionRow>` — `SELECT ... WHERE id = ... FOR UPDATE`. Critical for AC-MATCH-24 (HTTP decision + timeout job race).

In `packages/db/migrations/`:

- New migration file generated by `pnpm run db:generate` AFTER the schema is committed. Migration committed to git per control-manifest "Drizzle migrations checked in".

## Acceptance Criteria

- [ ] **Schema compiles**: `pnpm run db:generate` produces a migration. Migration applies cleanly with `pnpm run db:migrate` against a fresh test DB on port 5433.
- [ ] **Partial UNIQUE enforces**: INSERT session for playthrough P with `state='in_progress'`. Attempt second INSERT for same playthrough → throws `MatchSessionConflictError` (constraint violation). UPDATE first session to `state='completed'` → second INSERT now succeeds.
- [ ] **`'failed'` excluded from UNIQUE**: INSERT session for P, UPDATE to `state='failed'`. Attempt INSERT new session for P → succeeds (the failed row does NOT block — per ADR-013 §Session Lock).
- [ ] **Drizzle 0.36+ syntax**: the `.where()` clause uses `sql\`... NOT IN ('completed', 'archived', 'failed')\`` (template literal, not raw string). Grep the schema file: `where(sql\`` should be present, `where("` should NOT.
- [ ] **`findActiveSession` ordering**: insert two rows for P — first with `state='failed', created_at=10`, second with `state='in_progress', created_at=20`. `findActiveSession(P)` returns the `in_progress` row. R6 fix: ORDER BY DESC ensures the active row wins even if findFirst would have picked the older row.
- [ ] **`acquireForUpdate` blocks**: in a transaction T1, `acquireForUpdate(sessionId=X)`. From T2, `acquireForUpdate(X)` → BLOCKS (Postgres FOR UPDATE). After T1 commits, T2 proceeds. This is the AC-MATCH-24 lock primitive.
- [ ] **JSONB round-trip**: insert a session with a populated `MatchSessionSnapshot` (incl. yellowCardsByPlayerId as Record, eventsAccumulated as array). Read back via the repo. Deep equal to the original. No Map drift.
- [ ] **`updated_at` triggers**: a manual UPDATE to `state` causes `updated_at` to increment. Used by the recovery worker (story 018) to detect orphaned sessions.
- [ ] **Migration committed**: the generated migration file is present under `packages/db/migrations/`. `git status` reports clean after `pnpm run db:generate`.

## Implementation Notes

*From ADR-013 + control-manifest Foundation Required:*

- "Drizzle partial UNIQUE syntax: use `sql` template literal in `.where()` clauses, not raw strings (verified by slice — drizzle-kit generate fails otherwise)".
- "MatchSession partial UNIQUE (ADR-013): the unique index excludes states `'completed'`, `'archived'`, `'failed'`. A failed session must NOT block a new match start."

*From GDD R6:*

- The query canónica for `findActiveSession` uses `ORDER BY created_at DESC` to break ties when `failed` and `in_progress` coexist.

*From GDD §Recovery worker (R6) — not built here but the schema must support it*:

- `WHERE state = 'paused_for_decision' AND timeout_job_id IS NULL AND updated_at < NOW() - INTERVAL '2 minutes'` is the orphan-session query. Schema supports it.

## Notes / Gotchas

- **`sql` template literal is the slice's hard-won lesson**. Drizzle 0.36+ otherwise produces a "raw" partial index expression that drizzle-kit can't fingerprint, causing duplicate migration generation. The slice's PR comment trail documents this.
- **The migration must be committed**. If a developer runs `pnpm run db:generate` and forgets to commit, CI will fail (control-manifest required).
- **JSONB vs JSON**: Postgres jsonb is more efficient for indexed queries; use jsonb for all snapshot fields (Drizzle's `jsonb()` helper).
- **`yellow_cards_by_player_id` column**: jsonb. The schema does NOT enforce inner type — Zod validates at the application layer (when reading back via the repo). Defensive parse with Zod to catch any Map drift (regression on control-manifest forbidden Map<>).
- **The `seed` column** is stored as text for debugging. The PRNG state is the only authoritative source for resume — `seed` alone cannot be used to resume (Option B chose state over seed-+-replay).
