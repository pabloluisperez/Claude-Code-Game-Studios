# v2.0 — MMO + multi-sport vision

**Window**: 2028-Q4 → 2029-Q4+ (~12-18 meses)
**Status**: Vision (not committed)
**Owner**: Pablo + posible co-fundador / contractor
**Prev**: v1.3 cadence ≥ 6 meses estable
**Unlock criteria**: DAU/MAU > 0.2 sostenido + revenue justifica investment

Este es un documento de dirección, no de plan. Define la visión de lo que
v2.0 podría ser, los gates que justifican empezarla, y los workstreams
paralelos que requeriría. Es probable que cambie sustancialmente cuando
llegue el momento — el roadmap se actualiza basándose en lo aprendido en
v1.0-v1.3.

---

## 1. Why v2.0?

v1.x es un juego single-player de gestión deportiva. v2.0 expande en tres
direcciones que requieren replantear arquitectura, NO añadir features:

| Eje | v1.x | v2.0 |
|-----|------|------|
| Concurrencia | Single-player offline-friendly | MMO: ligas compartidas con managers humanos |
| Deporte | Football only | Sport-agnostic engine (multi-deporte) |
| Plataforma | Web (browser) + PWA | Web + native mobile + opcional desktop launcher |

Cada eje requiere ~6 meses de architecture work — los tres juntos justifican
una versión mayor "2.0".

---

## 2. Workstream A — MMO foundations

### 2.1 Hypothesis

> *"Si el loop de gestión es satisfactorio en single-player, jugarlo
> contra otros managers humanos lo multiplica — pero sólo si el tempo
> contemplativo se preserva (Pilar 4)."*

NO se trata de PvP en tiempo real. Se trata de **ligas compartidas**:

- 20 managers humanos (+ 0-20 AI managers) comparten una liga
- Cada uno avanza al ritmo propio dentro de una semana real
- Al final de la semana real, la jornada se procesa: todos los partidos
  se simulan con las decisiones que cada manager tomó
- Tabla común, mercado de fichajes común, prensa común (AI narrative
  habla de tus rivales reales)

### 2.2 Technical implications

| Component | Cambio v1.x → v2.0 |
|-----------|--------------------|
| WorldState | Single per-playthrough → multi-tenant shared league state |
| Determinismo | Mantener — partidos de jornada se procesan en orden fijo, no concurrente |
| Match-sim | Sin cambio funcional — sport-agnostic ya separado |
| Transfer market | Negociación asíncrona entre managers (mensajes) |
| Sync | Socket.IO ya existe (MVP) → activar para league updates |
| Schedule | BullMQ ya orquesta ticks → escalar a multiple leagues |
| Auth | Sigue session-based — sin novedad |
| Anti-cheat | Server-authoritative ya garantiza — sin novedad |

### 2.3 Estimated sprint count

20-30 sprints (10-15 meses).

## 3. Workstream B — Sport-agnostic engine

### 2.1 Hypothesis

> *"El 70% del engine es ya sport-agnostic — la separación se diseñó
> desde el principio. v2.0 ejecuta el corte y añade un segundo deporte
> como prueba."*

`apps/api/src/modules/match/` y `packages/shared/src/sim/` ya tienen
una separación entre core sim y reglas de fútbol. v2.0:

1. Extraer `SportRules` interface
2. Implementar `FootballRules` (refactor existente)
3. Implementar segundo deporte como validation

### 2.2 Candidate second sport

| Sport | Pro | Con |
|-------|-----|-----|
| Baloncesto | Mecánicas similares (equipo vs equipo, temporada, draft) | Match-sim time-model muy diferente (cuartos, posesiones) |
| Hockey | Estructura de liga similar; mercado de transferencias | Audiencia más pequeña |
| Béisbol | Mercado vibrante (USA, Japón, LATAM) | Match-sim muy distinto (innings, batting order) |
| **Fútbol americano** | Audiencia USA grande; mismas tactical decisions | Match-sim play-based, no time-based |

Recomendación inicial: **baloncesto** — máximo solapamiento con código
existente, mínimo nuevo content.

### 2.3 Estimated sprint count

8-12 sprints (4-6 meses) para extraer + implementar basketball.

## 4. Workstream C — Native mobile + cross-platform

### 4.1 Hypothesis

> *"PWA llega lejos pero hay user-experience que sólo native iOS/Android
> ofrecen (push notifications fiables, install fluido, app store
> discoverability)."*

### 4.2 Technology evaluation

| Stack | Pro | Con |
|-------|-----|-----|
| **Capacitor** | Reusa todo el código web; mínimo overhead | Performance ~85% nativo |
| **Tauri 2 mobile** | Más leve que Capacitor | Mobile support menos maduro |
| **React Native + Expo** | Native UI, comunidad grande | Reescritura completa de UI |
| **Flutter** | Native UI, performance excelente | Reescritura completa, dos codebases |

Recomendación inicial: **Capacitor** — minimal rework, time-to-market,
y compromiso aceptable de performance.

### 4.3 Estimated sprint count

6-10 sprints (3-5 meses) para wrap + store submissions iOS/Android.

## 5. Pre-requisites antes de arrancar v2.0

NO arrancar v2.0 hasta que TODOS estos estén verdes:

- [ ] v1.3 lleva ≥ 6 meses estable en producción
- [ ] DAU/MAU > 0.2 sostenido (signal de retención fuerte)
- [ ] Revenue (donations / premium) cubre operating cost + reservas
- [ ] Architecture review formal del refactor sport-agnostic aprobado
- [ ] Spike de MMO foundations (single league multi-user) PROCEED
- [ ] Privacy + security review pasado para MMO features (chat, transfer market)
- [ ] Team de >1 persona disponible (no realista hacer 3 workstreams solo en paralelo)

## 6. Funding scenarios

Solo dev hasta v1.3 es viable. v2.0 probablemente NO lo es sin algún tipo
de financiamiento o ayuda:

| Modelo | Pro | Con |
|--------|-----|-----|
| Bootstrap (donations + revenue v1.3) | Independencia | Slow growth |
| Indie publisher | Marketing + cash | Pierdes parte de IP control |
| Crowdfunding (Kickstarter) | Validates demand pre-investment | Riesgo de no entregar lo prometido |
| Angel / VC | Velocity max | Pressure de growth metrics, posible pivot forzado |
| Contractor part-time | Mantienes solo control | Bottleneck en hiring + management |

Recomendación inicial: **bootstrap si revenue v1.3 lo permite**, plan B
crowdfunding pre-v2.0 para validate demand + fund part-time contractor.

## 8. Things that should NOT be in v2.0

Explicit NO-list:

- ❌ Lootboxes / gacha — viola Pilar 4 Calm Is The Tempo
- ❌ Energy mechanics que fuerzan a esperar — anti-fun
- ❌ Pay-to-win — incluso freemium MMO debe ser cosmetic-only
- ❌ NFTs / blockchain — gimmick, no aporta al core fantasy
- ❌ Forced social features (compartir en redes para unlock) — viola Pilar 4
